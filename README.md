# Сборщик вакансий: сайты → SQLite → Telegram

Скрипт обходит сайты с вакансиями, забирает название, компанию, зарплату и ссылку,
складывает всё в SQLite и раз в сутки отправляет в Telegram только то, что появилось
с прошлого раза.

## Как запускать

```bash
pip install -r requirements.txt

python vacancy_watcher.py collect --pages 3   # обойти сайты, записать новое в базу
python vacancy_watcher.py send --dry          # посмотреть текст сообщения, не отправляя
python vacancy_watcher.py send                # отправить в Telegram
python vacancy_watcher.py run                 # собрать и сразу отправить
python vacancy_watcher.py stats               # что лежит в базе
python vacancy_watcher.py export              # выгрузить всё в Excel
```

Ключи: `--pages N` сколько страниц каталога брать, `--sites hh.ru,rabota.ru` только
эти источники, `--db файл.db` своя база, `--limit N` отправить не больше N штук.

Токен бота и чат берутся из окружения:

```bash
set TG_TOKEN=123456:AA...
set TG_CHAT=123456789
```

## Добавить новый сайт

Источник это просто набор селекторов в словаре `SITES`, остальной код не трогается:

```python
"geekjob.ru": {
    "page_url": "https://geekjob.ru/vacancies?page={page}",
    "card": "li.collection-item.avatar",
    "title": "p.vacancy-name a.title",
    "company": "p.company-name a",
    "salary": "span.salary",
},
```

Если у сайта классы генерируются сборщиком и меняются с каждым релизом (так на hh.ru),
цепляться нужно за `data-qa`, а зарплату брать поиском по тексту карточки:
`"salary": None, "salary_regex": True`.

Подобрать селекторы для незнакомого сайта помогает `probe.py`:

```bash
python probe.py https://example.com/vacancies
```

Он говорит, отдаётся ли содержимое сервером или дорисовывается скриптами, сколько на
странице вакансий и какие контейнеры их оборачивают.

## Дубли

Одна и та же вакансия попадает в выдачу по-разному, поэтому чистка двухслойная:

1. **По ссылке.** В базе `url UNIQUE`, повтор не запишется. Хвост запроса у ссылки
   отрезается: на hh.ru и rabota.ru туда подставляются метки поиска, из-за которых
   одна вакансия каждый раз выглядела бы новой.
2. **По содержимому.** Отпечаток `сайт + название + компания + зарплата`. Работодатели
   регулярно перевыкладывают вакансию под новым адресом, по ссылке она новая, по сути
   та же самая. На первом же прогоне таких набралось 13 из 100.

## Что с защитой сайтов

- **rabota.ru** отдаёт готовый HTML, берётся обычным запросом.
- **hh.ru** тоже отдаёт HTML, но классы в разметке хэшированные, поэтому разбор идёт
  по `data-qa`, а между страницами держится пауза, чтобы не словить капчу.
- **superjob.ru** закрыт капчей полностью: она приходит и на поиск, и на главную, и
  даже на `robots.txt`. Ни обычный запрос, ни headless-браузер с отключённым признаком
  автоматизации её не проходят. Нужен официальный доступ через `api.superjob.ru`
  (ключ выдают бесплатно на зарегистрированное приложение). Профиль сайта в коде уже
  лежит и заработает, как только доступ появится.

Если сайт вместо страницы отдаёт капчу, скрипт говорит об этом прямо и идёт дальше,
а не пишет молча ноль вакансий.

## Раз в сутки

Linux, `/etc/systemd/system/vacancy-watcher.timer`:

```ini
[Unit]
Description=Сбор вакансий раз в сутки

[Timer]
OnCalendar=*-*-* 09:00:00
Persistent=true

[Install]
WantedBy=timers.target
```

Windows, через планировщик:

```powershell
schtasks /create /tn "vacancy-watcher" /tr "python C:\path\vacancy_watcher.py run" /sc daily /st 09:00
```

## Что внутри

| файл | зачем |
|---|---|
| `vacancy_watcher.py` | сбор, база, дедуп, отправка, выгрузка в Excel |
| `probe.py` | разведка незнакомого сайта перед тем, как писать селекторы |
| `preview.py` | картинка с содержимым базы, удобно показывать заказчику |
